# 论文贡献点

建议把论文的创新/工作点收敛为三条，每条都能在代码和实验里找到对应证据。

## 贡献一：面向课程资料的三重拒答机制

**问题**：普通 RAG 只要检索到“相似段落”就会让模型回答，容易把相邻概念讲成答案（例如资料讲二叉树，学生问红黑树插入）。

**机制**：

1. 距离门控：top1 相似度低于阈值直接拒答；
2. 未收录标记：模型在提示词约束下输出统一“未收录”标记；
3. 可答性判定：检索通过后，再让模型判断资料是否“直接讲了这个问题”。

**代码**：`backend/services/rag_service.py`、`backend/services/rag_prompts.py`。

**实验**：`evaluation/golden.json` 中的 `near_miss` 类别；对比开关可答性判定前后的拒答准确率与误拒率。

## 贡献二：未命中问题驱动的资料补全闭环

**问题**：课程答疑中“答不上来”的问题最有价值，但普通系统答完就结束。

**机制**：

1. 未命中问题自动入库并按问题聚类；
2. 管理员补充资料后，一键重新生成回答；
3. 学生端可查看已解决问题，形成“提问 → 拒答 → 补料 → 再回答”的闭环。

**代码**：`backend/routers/unanswered.py`、`backend/routers/chat.py`、`backend/static/js/views/admin-feedback.js`、`feedback.js`。

**实验/演示**：`demo/seed_demo.py` 会生成 4 条未命中问题（3 条待处理、1 条已解决），可直接演示管理端流程。

## 贡献三：课程级可见性隔离与引用溯源

**问题**：课程资料可能包含教师私有库、不同班级的资料，不能所有学生都能检索。

**机制**：

1. 学生只能检索“公共库 + 自己创建的库”，公共库对非创建者只读；
2. 检索时按 `course` metadata 过滤，越权指定课程会被后端裁剪；
3. 回答附带引用来源，前端可回溯到具体知识点/文档。

**代码**：`backend/services/kb_scope.py`、`backend/services/vector_store.py`、`backend/routers/chat.py`。

**测试**：`test_course_visibility_and_write_guard`、`test_knowledge_base_visibility`、`test_student_cannot_access_admin_endpoints`。

## 与普通 RAG 的对比

| 能力 | 普通 RAG | 本系统 |
| --- | --- | --- |
| 检索 | 向量 top-k | 向量 top-k + 课程过滤 |
| 拒答 | 依赖模型自由发挥 | 距离门控 + 未收录标记 + 可答性判定 |
| 失败处理 | 答完即结束 | 未命中入库、聚类、补料、重新生成 |
| 权限 | 通常无 | 课程级可见性隔离 + 公共库只读 |
| 可追溯 | 可选 | 引用来源 + 原文片段 |
| 删除恢复 | 通常无 | 回收站快照 + 30 天恢复 |

## 答辩时怎么讲

- 先讲**问题**：课程答疑重复、不及时、口径不一致。
- 再讲**系统**：RAG 问答 + 课程隔离 + 反馈闭环。
- 重点讲**贡献**：三重拒答、未命中闭环、课程级隔离。
- 最后讲**实验**：recall@k / MRR / 拒答准确率 / 误拒率，以及消融对比。
- 现场演示：用 `demo/seed_demo.py` 的账号登录，展示问答、引用、拒答、反馈和管理端补料。
