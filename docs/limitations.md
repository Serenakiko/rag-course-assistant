# 已知限制与设计取舍

这份文档集中说明项目当前的边界。它们大多是「课程项目 / 单机部署」下的有意取舍，不是未发现的 bug；写论文和答辩时也应如实说明。

## 1. 默认管理员密码

- 默认账号是 `23040107`，默认密码是 `111111`。
- 默认值的唯一来源是 `backend/seed_data.py` 的 `DEFAULT_ADMIN`；`main.py`、`run.py` 和测试都引用它，避免多处硬编码漂移。
- 可以在 `.env` 里用 `DEFAULT_ADMIN_PASSWORD` 覆盖**首次创建**时的密码；账号已存在时不会覆盖，需在「个人中心」修改。
- 当 `HOST` 不是 `127.0.0.1 / localhost / ::1` 时，若管理员仍在用默认密码，`_guard_default_admin` 会直接拒绝启动。
- 因此：本机演示可以直接用默认密码；局域网或公网部署前必须改密，或设置 `DEFAULT_ADMIN_PASSWORD` 后重建管理员。

> 说明：仓库历史中不存在 `476030` 这个密码。README 与 `seed_data.py` 当前都是 `111111`；如果看到两者不一致，说明看的不是本仓库当前版本。

## 2. 限流状态在进程内

- 登录、注册、问答的限流都用 `threading.Lock + 进程内 dict`，重启即清空，多 worker / 多机之间不共享。
- `run.py` 默认单进程，因此当前行为是正确的；如果将来改用 `uvicorn --workers N` 或多实例部署，实际限额会被放大 N 倍。
- 扩展到多进程时需要把计数移到 Redis 等共享存储；这超出本科单机项目的范围。

## 3. 数据库迁移

- 项目没有使用 Alembic；`backend/database.py` 的 `init_db()` 通过 `PRAGMA table_info` + 条件 `ALTER TABLE` 做幂等增量补列。
- 这套做法适合 schema 基本冻结的课程项目，启动时自动把旧库对齐，不需要额外迁移命令。
- 如果后续持续迭代表结构，建议引入 Alembic，并把现有补列固化成一条基线迁移，避免 `init_db` 越来越长。

## 4. 评测集规模

- `evaluation/golden.json` 目前 40 条，来自 20 个种子知识点，包含标准问法、改写、完全无关和相近未覆盖四类。
- recall@5 = 1.0、MRR = 1.0 只说明**在这套小规模集合上检索已饱和**，不能外推到真实学生问题分布。
- 论文中应写明这是「小规模演示数据集」；更严谨的做法是收集一学期真实提问，扩充到 100 条以上后重新评测。

## 5. 拒答阈值与 embedding 模型耦合

- `UNMATCHED_SIMILARITY=0.56` 是按 `bge-m3` 在当前 20 个知识点上标定的；换 embedding 模型后必须重新跑 `python -m evaluation.evaluate --thresholds`。
- `vector_store` 会校验向量维度和 cosine space；同维度换模型时，会在 `data/chroma/embedding_model.txt` 记录模型名并在变化时打警告，避免阈值静默漂移。
- 如果语义空间差异较大，仅改阈值不够，需要删除 `data/chroma` 重建向量库。

## 6. 前端零构建

- 前端是原生 HTML/CSS/JS，没有打包步骤；静态资源靠 `?v=` 手动版本号和 `no-cache` 兜底。
- 这让部署非常简单，也让断网环境可用；代价是代码规模变大后，版本号和模块拆分需要人工维护。

## 7. 单机部署假设

- SQLite、ChromaDB、上传文件都落在本机 `data/` 目录，备份时需要整体复制。
- 没有对象存储、任务队列和反向代理配置；这些是生产化才需要的基础设施，不影响答辩演示。
