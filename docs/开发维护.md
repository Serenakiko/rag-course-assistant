# 开发维护

接手维护时最该先读的踩坑记录、测试清单与前端规范。

## 一、测试与验收

### 测试策略

按"能不能自动化"分层：业务规则与边界用单元测试钉住；前端纯函数用 node 回归；连模型与数据库的
链路用手工端到端脚本验收；性能与安全单独记录。

| 层次 | 工具 | 数量 | 覆盖内容 | 是否依赖模型 |
| --- | --- | --- | --- | --- |
| 后端单元 | pytest | 27 | 可见性、门控、限流、分页、并发闸门、提示词装配 | 否（模型用 fake） |
| 前端纯函数 | node + `vm` | 2 | 分页条行为、Markdown 转义与链接白名单 | 否 |
| 端到端 | Python 脚本（urllib） | 4 组 | 登录、列表、问答、拒答、上传入库、检索命中 | 是 |
| 性能 | 计时脚本 | — | 冷/热启动、首 token、整轮耗时、测试套件耗时 | 是 |
| 安全 | 单测 + 用例 | — | XSS、越权、限流、令牌失效 | 部分 |

| 指标 | 实测值 | 说明 |

## 二、踩坑记录

**1. 为什么是 Chroma + SQLite 两套存储**
知识点要能改能删、要按创建者鉴权、要知道谁改的，这些在向量库里做很别扭。最后 SQLite 存元数据，
Chroma 只存文本和检索字段，两边靠 `doc_id` / `point_id` 关联。代价是增删要两边各来一次，
所以 `vector_store.py` 的删除都按元数据过滤，没有按 id 删。

**2. 分块参数是试出来的**
块太短会把知识点拦腰截断，检索回来是半句话。最后定成 800 字、重叠 120；`chunker.py` 除了按
段落和换行切，还排了中文标点的优先级，避免整段没有句号的课件被硬切。

**3. 拒答这一层是被模型逼出来的**
最早没有距离门控，模型拿自己的知识开始编。最典型的是问「红黑树」，库里只有二叉树，它照样把
红黑树的性质讲了一遍。所以加了 `UNMATCHED_DISTANCE`：最相似资料的距离超过阈值就直接判
「知识库没收录」，拒答文案由系统拼。阈值是拿 18 条问题实测标出来的：

| 分组 | 最低 | 最高 |
|---|---|---|
| 库里有答案（栈、TCP、进程线程、死锁、快排、哈希表等） | 0.4631 | 0.7749 |
| 库无但话题沾边（红黑树、B+ 树、AVL、协程等） | 0.9133 | 1.0523 |
| 完全无关（天气、考公） | 1.1882 | 1.2134 |

中间 **0.78 ~ 0.91 的空带**就是阈值该待的位置，取 **0.85**。最初拍脑袋的 1.10 落在「该拒答」
档里，那 6 个沾边问题一个都没拦住。

**4. 阈值和向量模型绑死**
同一批问题换向量模型后分数整体平移，阈值会把所有问题都拒掉。所以阈值放在 `.env` 里，
换模型必须重新标定并重建向量。

**5. 拒答把反馈列表搞脏了**
「今天天气怎么样」「考公怎么选岗」也会进反馈，管理员一屏全是垃圾。所以拒答前先过
`is_course_related()`：明显课程术语直接相关，明显无关的直接不记录，剩下的交给模型二分类。

**6. 「这门课讲了什么」被门控误伤**
这类问题和资料的字面相似度很低，但它恰恰最该答。所以单独做了 `OVERVIEW_PROMPT`：不做
未收录判定，只汇总介绍检索到的资料。

**7. 阈值 0.85 的两处代价**
宽泛问题（「帮我总结这门课的核心框架」）实测 1.09，会被判未覆盖；话题混搭的问题
（「红黑树和二叉查找树有什么区别」）仍可能拿到 0.73 的距离被放行，然后模型照着二叉树编红黑树。

**8. 第三层防线在 3B 上不成立（默认关闭）**
曾尝试在检索后再问一次「资料里有没有直接讲这个问题」。当时用 qwen2.5:3b 试了 6 种提示词：
要么恒定回答「没有」，要么在明明有依据时也说「无」。只给一句话的极简资料判定正确，给 3 段真实
检索结果就失灵。所以 `ANSWERABILITY_CHECK=false`，代码保留。要启用，建议单独指给 7B 以上的模型。

**9. qwen3.5 的思考模式会吃空回答**
换成 qwen3.5:4b 后，第一次实测返回的 `response` 是空字符串——模型把预算全花在 `thinking` 里了。
解决方式是 `ChatOllama(reasoning=False)`；同时把 `num_ctx` 显式设成 8192，否则多轮对话加资料
很容易把系统规则挤出 4096 的默认窗口。

**10. Ollama 升级后模型"消失"**
桌面端某次升级把模型目录解析到了 `D:\` 根目录，`ollama list` 空空如也，日志里是
`total blobs: 0`。模型其实都在 `C:\Users\<你>\.ollama\models`。结论：Ollama 的模型目录以
桌面端设置为准，不是环境变量；升级后先看设置里的存储位置。

**11. 拉模型卡在 IPv6**
Ollama 下载器连 Cloudflare R2 时走 IPv6，某些网络环境下会一直 `SynSent`。最后用 `curl -4`
手动下载层文件 + 校验 SHA256 + 写回 manifest 才装上。遇到「pulling manifest」长时间不动，
先怀疑 IPv6。

**12. 回收站用快照，不做软删除**
一开始想在知识库表上加 `deleted_at` 做软删除，问题是删除知识库本来就要清向量、删文档、搬源文件，
软删除会把这些「要不要真删」的分支渗进检索、列表、统计所有查询里。最后改成独立的 `RecycleItem`
快照表：删之前存一份库信息 + 知识点正文 + 文档元信息，源文件移到 `data/trash/<id>/`，主表照常
真删。恢复时按快照重建并重新向量化。代价是恢复要重跑 embedding，几秒量级，能接受。

**13. 未命中问题曾经按主键重排，误删过记录**
最早删一条反馈就把其余记录的 id 前移，前端或脚本手里的旧编号立刻指向别人，按编号删就打偏了。
现在主键一律不动，只重排展示用 `display_no`。

**14. 聚类不能只靠字面匹配**
中文不分词，按字面相似度合并会漏掉「红黑树怎么插入」和「红黑树的插入过程」这种换说法。所以
优先用 bge-m3 余弦（0.78），向量不可用时才退回字符二元组 Jaccard（0.55）——宁可分组粗一点，
也不要因为模型挂了就整页空白。问题向量单独存一张缓存表，同一句话只算一次。

**15. 失败不能写成「已解决」**
管理员点「生成回答」时，超时或空回答曾经也会清状态，结果学生端显示已解决但内容是空的。现在
`generate_answer` 明确返回 `error` 字段，超时 / 空回答保持待处理、不覆盖已有答案。

**16. 知识库和文档本来是两个菜单**
补资料时要在「知识库管理」和「文档管理」之间来回跳，管理员反馈很烦。现在合并成一个
「知识库与文档」页，两个 tab 各管一摊，上传入口收进编辑弹窗，旧路由（`kb` / `documents`）
仍能落到对应 tab。

**17. 改了前端却不生效：静态资源被缓存**
`app.html` 里每个 js/css 都带 `?v=NN`。改了文件不提版本号，浏览器会继续用缓存里的旧代码。
现在 `main.py` 给 `/static` 统一加了 `Cache-Control: no-cache`，但**改 js/css 仍然要同步提
`?v=`**：已经打开过的页面不会主动回源，而且版本号本身能标记"这次改过"。

**18. 「已解决」的反馈重新生成失败后变成空白答案**
管理员在「已解决」tab 点「重新生成」，如果知识库里仍然没收录，`regenerate` 的 `else` 分支只清了
`q.answer`，`status` 还留在 `resolved`：学生端看到「已解决 + 新回答」角标、点开是空白。现在
`else` 分支同时把 `status` 打回 `pending`、`answered_at` 清空。

**19. 学生端反馈只取最新 50 条，统计数字跟着少算**
`/api/chat/unanswered/mine` 原来写死 `.limit(50)`，前端按 10 条/页只能翻 5 页，第 51 条以后学生
永远看不到；「待处理 / 已解决」两个数字还是从这 50 条里 `filter().length` 算出来的。现在改成
服务端分页，两个计数单独按全量查。改返回形状时还漏了一处：首页「我的反馈」卡片
（`views/workbench.js`）仍把响应当数组 `.slice()`，一渲染就抛 `TypeError`。接口从数组改成
`{total, items}` 这类对象时，务必把所有调用方一起扫一遍。

**20. 聊天页整页能上下滑，输入框被顶出屏幕**
`.chat-layout` 之前写死 `height: calc(100vh - 108px)`，但实际可用高度是
`100vh - 60(header) - 24 - 76(上下内边距) = 100vh - 160`，多算 52px 就把 `.main-content`
撑出了滚动条。现在改成 `height: 100%` 跟随父容器 + `min-height: 0` 允许被压缩，只有
`.chat-messages` 自己滚。

**21. 滚动条**
`common.css` 里原来是 `* { scrollbar-width: none }`，全站都不画滚动条。**但这等于把「这页还能
往下」的唯一视觉线索一起藏了**。现在改成 8px 细条 + 透明轨道：不溢出时什么都不显示，真溢出时
露出一根浅色把手当提示。顺带配色：页面底色 `#f6f5f2` 和消息区 `#f7f6f3` 只差一个色阶，卡片
原来的 `--shadow` 几乎等于没有，现在卡片给了 1px 边框 + `--shadow-lg`，聊天页容器底色压到
`#e9e4db`，卡片横向居中、最多 1280px。

**22. 同一会话允许两轮并发 = 上一问丢答案**
`abortController` 是 `await API.streamAsk()` 之后才赋值的，可按钮那时已经变成「停止生成」——
这段建连空窗期点按钮走的是「发送」分支，于是第二轮发起来了。后端 `_gen_seq` 发现同会话有新请求
会把旧一轮作废（不落库），库里留下一条没答案的提问，界面上那个气泡永远转圈。现在 `streamAsk`
同步返回 `{ controller, done }`（建连阶段也能 abort），`send()` 开头就用 `activeSeq` 同步占位，
并发提问在点击那一刻就被挡住。

**23. 上一轮回答里有花括号，下一轮就报「回答生成失败」**
多轮历史原来是 `("user", "文本")` 元组直接塞给 `ChatPromptTemplate.from_messages()`，LangChain
会把每条消息当模板解析：上一轮回答里出现 `if (x) { ... }` 或 JSON，格式化时就 `KeyError: ' '`。
现在历史与学生问题都改成 `HumanMessage` / `AIMessage` 对象（内容不再参与模板解析），系统提示仍
保留 `{context}` 占位。

**24. Chroma 的 where 平铺两个键会直接抛错**
文档详情的分块是这么查的：`collection.get(where={"source_type": "document", "doc_id": str(doc.id)})`。
Chroma 只认「一个操作符」，两个键平铺会抛 `ValueError: Expected where to have exactly one operator`；
外面正好套了 `try/except` 兜成空列表，于是文档详情永远显示「没有分块」。多条件必须写
`{"$and": [...]}`（`vector_store.delete_document` 早就这么写了，这里是漏了一处）。

**25. 一个问题打一次模型，并发不限 = 全批超时**
每个人提问都会打一次模型（未命中还要多打一次「是否课程相关」）。本机 3B 模型一次只吐一路 token，
30 个人同时点发送时，排在后面的请求等不到第一个 token，180 秒后整批超时。现在 `stream_answer`
外面套了一层信号量（`_llm_slots()`，默认 `_SLOT_COUNT = 3`）：同时最多 3 路生成，排队的请求每
10 秒收一个 `ping` 保活，槽位在 `finally` 里释放，里层生成器 `aclose()`——客户端断开时模型流
不会吊在那儿。第一批改完还有三个洞：① 排队没有上限——现在排队满 120 秒就回明确的 `error`；
② 非流式的 `generate_answer` 没进闸门——现在它和流式共用 `_llm_slots()`，最多等 120 秒就回
`busy`；③ 模块级单个 `Semaphore` 跟事件循环绑死——pytest 每个 `asyncio.run()` 都是新循环，
所以改成 `_llm_slots()` 按 loop 惰性取。

**26. admin.js 一个文件塞了五个页面**
1231 行里混着数据概览、用户管理、知识库表格、对话历史、问题反馈。现在问题反馈整体拆成
`views/admin-feedback.js`（独立 IIFE），`AdminView.render(container, "unanswered")` 委托过去，
admin.js 降到 969 行。

**27. 一堆「回答范围」代码，前端从来没调过**
`AskRequest.knowledge_bases`、会话里的 `knowledge_bases` / `last_knowledge_bases`、
`list_sessions` 的 `kb` 筛选：后端一直支持"这次只在某几个知识库里检索"，但界面上没有任何入口，
`streamAsk` 永远发空数组。更糟的是那段 403 校验写在「保存用户提问」**之后**——越权请求会先落一条
提问再返回 403。既然没人用，索性连功能一起删（模型里那两列保留并标成遗留列）。顺带删掉两个
前端从不调用的端点 `GET /api/knowledge/points`、`GET /api/knowledge/courses`。

**28. 默认管理员 + 放开 HOST = 后门**
`23040107 / 111111` 是本地课设的取舍，登录限流只拦暴力破解、拦不住已知密码。默认
`HOST=127.0.0.1` 时它出不了本机；但只要为「让同学用手机访问」把 `HOST` 改成 `0.0.0.0`，
这就是个公开的管理员入口。现在启动时检查：`HOST` 不是回环地址、管理员又还在用 `111111`，
直接拒绝启动。

**29. 侧边栏分组重排：高频入口提级，管理端入口归位**
学生端「智能问答」原本埋在「学习」组里——它是最常点的入口，却排在首页下面第二组。现在学生端把
「智能问答」提为一级入口，原「学习」组改名「学习记录」，「资料」组改名「课程资料」；管理端
「智能问答」移入「教学运营」、「回收站」移入「内容管理」，三组改名「内容管理 / 教学运营 / 系统管理」。
改动只在 `static/js/app.js` 的 `NAV` 里——`renderNav()` 只按顺序拼、不认分组名。

**30. 还没解决的**
- 文档解析（PDF/TXT 分块 + 入库向量）还是同步跑在后台线程里，一次传十几个大文件会排队。
- 多轮历史是「6 轮 + 6000 字」双上限，没按 token 算预算，换模型上下文变长后这套常数要重看。
- 聚类是贪心合并，长尾问题多时分组顺序会受输入顺序影响。
- 端到端回归仍靠 `.tools/kb_e2e.py`，没接进 CI；前端除分页条与 Markdown 的 node 回归外，其余交互还是靠人眼看。
- 「回答范围（只查某几个知识库）」整套后端逻辑已经删了，真要做就得在聊天页加多选入口。

**31. 启动 44–94 秒，根因不在业务代码**
`-X importtime` 显示 `langchain_text_splitters` → `sentence_transformers` → `transformers`
一条链吃掉了 28 秒——而项目根本不用 transformers（向量化走 Ollama 的 `bge-m3` HTTP 接口）。
两处处理：① 卸掉孤儿包；② `chunker.py` 的 `RecursiveCharacterTextSplitter` 改成在
`split_text()` 里延迟导入。实测启动 44–94 s → 13–16 s，pytest 196 s → 13.5 s。

**32. 顺手做的结构收口**

  `services/rag_prompts.py`，`rag_service` 继续 re-export 这些名字。
- `seed.py` 358 行 → 69 行：四门课程的示例知识点移到 `seed_data.py`。
- 加了 `pyproject.toml`（ruff：120 列 + E/F/I；pytest 的 `testpaths`）。
- 前端补了 `tests/frontend_markdown.mjs`：22 条断言钉住"先转义后渲染、危险协议不生成链接"。

## 三、前端设计规范（Design Tokens）

所有 token 定义在 `backend/static/css/common.css` 的 `:root` 中，全站样式只能引用这些变量，
禁止再写裸色值 / 裸圆角 / 裸 z-index（少数语义特殊的保留值见文末说明）。

### 设计取向

整套 UI 走**「暖纸感」**路线，而非框架默认蓝 / Notion 冷灰风：米白底（非纯白）长时间阅读不刺眼；
暖墨色文字（不用纯黑）；深青主色（刻意避开框架默认蓝）；层级靠留白和分隔线表达，不靠阴影堆叠。

### 颜色体系

| token | 值 | 用途 |
| --- | --- | --- |
| `--primary` | `#17505e` | 关键动作、选中态、链接 |
| `--primary-dark` | `#0f3b46` | 主色 hover |
| `--primary-light` | `#e7eff1` | 主色浅底（选中背景、徽章底） |
| `--accent` | `#b0762c` | 强调色（点缀，慎用） |
| `--success` / `--warning` / `--danger` | `#2f7d54` / `#96661a` / `#a83e33` | 成功 / 警告 / 危险 |

灰阶命名只表达「深浅层级」，不绑定具体场景：

| token | 值 | 层级 |
| --- | --- | --- |
| `--bg` | `#f6f5f2` | 页面底（最浅的暖纸） |
| `--card` | `#ffffff` | 卡片 / 白底 |
| `--surface-1` | `#faf9f7` | 表头底、输入框底、列表 hover |
| `--surface-2` | `#f1efec` | 列表项 / 标签 / 按钮 hover |
| `--surface-3` | `#e6e3dc` | 行内代码底、分隔符 |
| `--surface-4` | `#f7f6f3` | 消息区底 |
| `--chat-page-bg` | `#e9e4db` | 聊天页专属压深底色 |
| `--border` | `#e3e0d9` | 边框 |
| `--text-inverse` | `#ffffff` | 反白文字 |

状态色必须有区分度（可访问性），「浅底 + 深字」成对出现：

| 浅底 token | 深字 token | 场景 |
| --- | --- | --- |
| `--success-bg` `#eaf3ed` | `--success` | 成功 / 已就绪 |
| `--warning-bg` `#f6f0e5` | `--warning` | 警告 |
| `--danger-bg` `#f7ebe8` | `--danger` | 危险 / 失败 |
| `--notice-bg` `#faf3e2` + `--notice-border` `#dcc07e` | `--notice-text` `#7d5b1a` | 待处理提示 |

### 圆角体系（四档）

| token | 值 | 用途 |
| --- | --- | --- |
| `--radius-sm` | `4px` | 图标、标签、行内小元素 |
| `--radius` | `6px` | **基准**：按钮、输入框、普通卡片 |
| `--radius-lg` | `10px` | 卡片、弹窗、登录卡 |
| `--radius-pill` | `999px` | 胶囊：徽章、标签、分段按钮 |

> 圆形元素（头像、圆形按钮、加载点）用 `border-radius: 50%`，表达的是「圆形」而非「圆角」。

### 阴影体系（三档 + 聚焦环）

| token | 值 | 用途 |
| --- | --- | --- |
| `--shadow` | `0 1px 2px rgba(29,27,24,.05)` | 卡片 |
| `--shadow-lg` | `0 2px 10px rgba(29,27,24,.09)` | 弹窗 / 浮起（hover） |
| `--shadow-xl` | `0 8px 28px rgba(0,0,0,.16)` | 抽屉 / 浮层 |
| `--focus-ring` | `0 0 0 3px rgba(23,80,94,.12)` | 输入框 / 键盘聚焦环 |

### z-index 层级刻度

| token | 值 | 用途 |
| --- | --- | --- |
| `--z-backdrop` | 15 | 抽屉背板遮罩 |
| `--z-docked` | 20 | 侧栏 / 分页条等常驻元素 |
| `--z-drawer` | 30 | 抽屉本体 |
| `--z-skip` | 200 | 键盘跳转链接 |
| `--z-modal` | 1000 | 弹窗遮罩 |
| `--z-toast` | 2000 | 全局提示 |

### 间距

统一到 4px 网格，常用档位：`4 / 8 / 12 / 16 / 20 / 24 / 32`。避免出现 `13px`、`17px` 这类
脱离网格的间距。

### 语义特殊的保留值（不 token 化的理由）

| 值 | 位置 | 保留理由 |
| --- | --- | --- |
| `#e9edee` / `#cfdbdd` | 学生首页 hero 底 + 边框 | 青色系，与暖纸 surface 不同，仅此页用 |
| `#f8f7f4` | 上传区底 | 比 `--surface-1` 更接近页面底，仅此一处 |
| `#e6e3dc`（pre 前景） | 深色代码块文字色 | 是深底上的浅字，语义不是 surface |
| `0 0 0 1000px #fff inset` | 登录 autofill 遮罩 | 浏览器自动填充 hack |
| `0 0 0 2px rgba(23,80,94,.2)` | 头像选中环 | 选中态（2px 实环） |
| `inset 3px 0 0 0 var(--primary)` | 侧栏激活项左边条 | 左侧竖条标记 |
| `#6b675f` | 若干次要文字 / 图标 | 介于 `--text-2` 与 `--text-3` 之间的灰，低频 |

### 换主题 / 暗色模式

由于所有样式都引用 token，换主题只需在 `:root` 覆盖变量，无需改任何组件样式：

1. 覆盖 `--bg` / `--card` / `--surface-1~4` / `--border`（灰阶体系）。
2. 覆盖 `--text-1/2/3` / `--text-inverse`（文字体系）。
3. 覆盖 `--primary` / `--success` / `--warning` / `--danger` 及对应 `*-bg` 浅底。
4. 阴影和圆角通常不变。

### 维护约定

- 新增样式**先查 `:root` 是否有现成 token**，没有且属于「重复出现」的才新增 token。
- 低频独有色（出现 ≤ 2 次且语义独特）允许保留硬编码，但**必须加一行注释说明理由**。
- 修改现有视觉前，先跑 `anti-ui-slop-studio` 的自检脚本对比硬编码色值数，确认是「收拢」而非「新增散值」。
