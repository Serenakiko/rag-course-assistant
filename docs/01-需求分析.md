# 需求分析

> 本文档是毕业论文「需求分析」一章的素材，按可以直接改写进论文的粒度编写。
> 文中数字与系统实现一致（2026-10 版本）：8 个后端路由模块、47 个接口、9 张业务表、
> 11 个前端视图模块、23 个自动化测试用例。

## 1. 项目背景与建设目标

高校课程答疑长期依赖课堂提问、课程群与教师邮箱，存在三个问题：

1. **重复问题多**：同一知识点每个学期被反复追问，教师精力被重复消耗；
2. **答疑不及时**：非工作时间的问题往往要等到下次课才能回应；
3. **回答口径不一致**：不同助教、不同资料给出的解释详略不一，甚至互相矛盾。

本系统的目标是构建一个**基于 RAG（检索增强生成）的课程智能问答平台**：以课程资料（课件、
知识点、习题）为唯一知识来源，由大模型生成回答并给出引用出处；当知识库覆盖不到时拒答并
记录反馈，由教师补充资料后再闭环回复。系统同时提供教师侧的内容管理、数据统计与用户管理，
形成"提问—答疑—补资料—再答疑"的完整链路。

建设目标可概括为四条：

| 编号 | 目标 | 验收口径 |
| --- | --- | --- |
| G1 | 学生能就课程内容获得有出处的回答 | 回答附引用来源，可点开看原文片段 |
| G2 | 不知道就说不知道，不编造 | 知识库未覆盖时拒答并引导换问法，不产生幻觉答案 |
| G3 | 教师能看到学生问不到的问题并补齐资料 | 未命中问题可聚类、可一键重新生成回答、学生端可见 |
| G4 | 内容与用户可管理、误删可恢复 | 知识库/文档/知识点/用户增删改查，删除进回收站 30 天 |

## 2. 用户角色与权限

系统只有两类角色，登录后按角色装配不同的侧边栏与接口权限。

| 能力 | 学生 | 管理员 |
| --- | --- | --- |
| 注册 / 登录 / 改资料 / 改密码 | ✅ | ✅（管理员由系统预置，不开放注册） |
| 智能问答（检索范围） | 仅"管理员发布的 + 自己创建的"知识库 | 全部知识库 |
| 新建知识库 / 维护知识点 | ✅（自己的库） | ✅（全部） |
| 上传文档 | ✅（自己的库） | ✅（全部） |
| 删除知识库 | 仅自己的库 | 全部，且进回收站 |
| 查看未命中反馈 | 只看自己的 | 全部，可聚类、可重新生成回答 |
| 对话历史 | 只看自己的 | 全部 |
| 用户管理 / 回收站 / 数据概览 | ❌ | ✅ |

权限规则的实现集中在 `backend/services/kb_scope.py`（可见性）与 `backend/deps.py`
（`get_current_user` / `require_role`），不在各接口里散落判断。

| 编号 | 功能 | 需求说明 | 优先级 |
| --- | --- | --- | --- |

| F-A3 | 回收站 | 删除快照列表、按名称/删除人搜索、剩余可恢复天数、恢复或彻底删除 | 中 |

### 3.3 核心业务需求（问答链路）

1. **检索**：问题向量化后在可见范围内检索 Top-K 资料（文档分块 + 手工知识点同库）。
2. **门控**：最相似距离超过阈值判定"知识库未覆盖"，直接拒答并记录反馈。
3. **生成**：组装"系统规则 + 参考资料 + 最近 6 轮历史"的提示词，流式生成。
4. **溯源**：回答附带引用来源（标题、课程、片段摘要），前端可展开查看。
5. **闭环**：管理员补充资料后重新生成回答，学生在"我的反馈"中看到结果并标记已读。

## 4. 前端需求分析

前端是本系统使用频次最高的部分，也是论文重点之一。需求按"导航 → 页面 → 交互 → 状态"
四层拆解。

### 4.1 导航结构

侧边栏按"角色 → 分组"组织，一级入口放高频动作，账号类入口放最后一组：

```
学生                                    管理员
├─ 首页                                 ├─ 数据概览
├─ 智能问答                             ├─ 内容管理：知识库与文档 / 回收站
├─ 学习记录：对话历史 / 我的反馈          ├─ 教学运营：问题反馈 / 对话历史 / 智能问答
├─ 课程资料：知识库 / 我的文档            ├─ 系统管理：用户管理
└─ 账号：个人中心                        └─ 账号：个人中心
```

需求要点：

- **N1** 导航由 `NAV` 配置驱动，按角色过滤，新增页面只改配置与 `switch` 分支，不改结构；
- **N2** 当前项高亮、页面标题与导航项一致；管理员的旧入口（知识库/文档）合并进"知识库与文档"；
- **N3** ≤640px 自动切抽屉导航，支持遮罩点击、Esc 关闭、打开后焦点进入首个菜单项。

### 4.2 页面级需求

| 页面 | 必须出现的要素 | 关键规则 |
| --- | --- | --- |
| 登录/注册 | 账号、密码、注册入口、错误提示 | 登录失败有次数限制；注册校验学号格式与重复 |
| 首页 | 4 张统计卡、功能入口、反馈列表 | 整页一屏，不出现滚动条；卡片可点击跳转 |
| 智能问答 | 会话列表、消息区、输入框、停止生成按钮、引用卡片 | 流式逐字渲染；生成中禁用输入；引用可展开原文 |
| 对话历史 | 搜索框、表格、分页条、详情弹窗 | 服务端分页；删除有二次确认 |
| 我的反馈 | 统计卡、Tab、列表、分页 | 新回答高亮；点开即标已读 |
| 知识库 | 搜索、卡片网格、新建按钮、分页 | 固定 12 条/页，不显示"第 x/y 页" |
| 我的文档 | 上传、搜索、表格、分页、内容查看 | 解析中状态轮询；失败可重新解析 |
| 数据概览 | 4 张卡、趋势图、环形图、未命中列表 | 一屏放下；卡片可点击进对应页 |
| 知识库与文档 | 两个 Tab、表格、分页、编辑弹窗 | 弹窗内可直接上传文档 |
| 回收站 | 列表、搜索、剩余天数、恢复/彻底删除 | 彻底删除二次确认 |
| 问题反馈 | 统计、4 个 Tab、分页、生成回答 | 聚类 Tab 按人数排序 |
| 用户管理 | 搜索、表格、分页、新增/改角色/重置密码 | 删除显示用户名并清理会话 |

### 4.3 交互需求

- **I1 流式渲染**：SSE 事件逐 token 追加到气泡；首 token 可能十几秒，期间显示"思考中"。
- **I2 单轮串行**：同一会话一次只能有一轮生成，生成中按钮变"停止生成"，输入框不可提交
  （前端 `activeSeq` 占位 + 后端 `_gen_seq` 兜底）。
- **I3 停止与续答**：点停止立即断开并提示；重新打开被中断的会话自动补生成，且不重复记录提问。
- **I4 统一分页**：所有列表页共用 `Common.renderPagination`，管理员端不显示"第 x/y 页"，
  学生端按页面传 `hidePageInfo`。
- **I5 状态提示**：成功/失败用 toast；不可逆操作用确认弹窗；空态与加载态都有明确文案。
- **I6 零构建**：原生 HTML/CSS/JS，服务端直接托管，改完刷新即生效（需提 `?v=` 版本号）。

### 4.4 前端非功能需求

| 编号 | 需求 | 说明 |
| --- | --- | --- |
| NF-F1 | 响应式 | ≥1024 桌面双栏；≤640 抽屉导航；表格在窄屏横向滚动 |
| NF-F2 | 可访问性 | 次要文字对比度达 AA；键盘焦点环可见；提供"跳到主要内容"；尊重"减少动效" |
| NF-F3 | 安全渲染 | 模型输出先整体转义再解析 Markdown；只放行 http/https/mailto/站内相对路径 |
| NF-F4 | 首屏无外部依赖 | 字体、图标、Markdown 渲染全部本地实现，断网可用 |
| NF-F5 | 可维护 | 每个页面一个视图模块，暴露 `render(container)`；重逻辑（分页条、Markdown）独立成模块并有 node 回归 |

## 5. 非功能需求

| 编号 | 类别 | 需求 | 当前实现 |
| --- | --- | --- | --- |
| NF1 | 性能 | 冷启动 ≤ 20 s | 实测 10.1–13.2 s（单进程，SQLite + Chroma 本地） |
| NF2 | 性能 | 单轮回答首 token ≤ 30 s（4B 本地模型，热态） | 实测热态 10–15 s |
| NF3 | 并发 | 同时 3 路生成，其余排队并保活 | `_SLOT_COUNT=3`，每 10 s 心跳，排队上限 120 s |
| NF4 | 可靠性 | 模型超时/报错/手动停止不写成正式回答 | 超时 180 s；失败只落占位提示且不标中断 |
| NF5 | 安全 | 密码不可逆存储、令牌可失效 | PBKDF2-SHA256（10 万次）+ JWT（含 `ver`，改密即失效） |
| NF6 | 安全 | 接口级角色校验，学生不能越权检索 | `require_role` + `visible_course_names` 贯穿检索/列表/写入 |
| NF7 | 安全 | 登录与注册限流 | 登录：同账号+IP 10 分钟 10 次失败锁定；注册：同 IP 10 分钟 5 次 |
| NF8 | 安全 | 上传文件校验 | 仅 PDF/TXT/MD/CSV，≤20 MB，头像按文件头校验 |
| NF9 | 可维护性 | 代码规范与回归 | `pyproject.toml`（ruff）+ 23 个自动化用例 |
| NF10 | 兼容性 | Windows / macOS / Linux 均可运行 | 依赖纯 Python，无编译型依赖 |

## 6. 典型用例

### UC-1 学生提问并得到带出处的回答

- **参与者**：学生
- **前置**：已登录；知识库中有相关课程资料
- **主流程**：
  1. 学生进入"智能问答"，输入"TCP 三次握手为什么不是两次"；
  2. 前端建立 SSE 连接，服务端在可见范围内向量检索 Top-5；
  3. 最相似距离 ≤ 0.85，进入生成；提示词注入参考资料与最近 6 轮历史；
  4. 模型流式输出，前端逐字渲染，结束时展示 2 条引用来源；
  5. 回答与引用 JSON 落库，学生可刷新会话继续追问。
- **异常流**：
  - 距离 > 0.85 → 拒答，记录未命中问题，推荐相近资料标题；
  - 模型 180 s 未完成 → 停止生成，落"没有生成出回答"提示，不标中断；
  - 同一会话已有生成 → 旧请求被新序号顶掉，不再占一路模型。

### UC-2 教师补充资料后回复未命中问题

- **参与者**：管理员
- **前置**：存在待处理的未命中问题
- **主流程**：
  1. 管理员在"问题反馈"看到聚类结果（同义问法合并，按人数排序）；
  2. 上传新课件或在知识点里补充内容，系统自动分块入向量库；
  3. 点击"生成回答"，服务端按**提问学生当时的可见范围**重新检索并生成；
  4. 成功则状态置"已解决"并记录回答时间，学生端出现未读标记；
  5. 学生点开后标记已读。
- **异常流**：仍判未收录 → 保持"处理中"并提示继续补充；生成失败 → 不覆盖旧答案，按原因提示（排队未排上 / 超时 / 空回答）。

### UC-3 误删知识库并恢复

- **参与者**：管理员
- **主流程**：
  1. 删除知识库前，系统先落快照（库信息 + 知识点正文），文档源文件移入 `data/trash/<id>/`；
  2. 列表进入"回收站"，显示剩余可恢复天数（30 天）；
  3. 恢复时重建知识点与文档分块并重新向量化，重名自动加"（恢复N）"后缀。
- **异常流**：超过 30 天 → 启动时自动清理快照与归档文件，不可再恢复。
